Overview

Haboob pulls pump.fun activity off-chain through Helius, scores four signals against your own recent history, and folds them into a single 0–100 index mapped to a weather condition. One number, readable in five seconds.

The four signals

Each signal is scored 0–100 on its own, then weighted into the final index. Two of them are inverted, so that on every card higher always means better weather.

Graduationweight 35%

What share of newly created tokens actually made it off the bonding curve to Raydium. The strongest single signal of a healthy market.

Volumeweight 30%

Total SOL traded across pump.fun swaps in the window, measured against your own typical volume rather than any fixed target.

Rug rateweight 25%

A token counts as rugged once its creator has sold more than 80% of what they held, within 24 hours of launch. The dashboard shows the rate; the 0–100 score under it is inverted, so a low rate scores high.

Volatilityweight 10%

The median price swing across the busiest tokens. Shown as the swing itself; the score under it is inverted, so a calm market scores high and a violent one scores low.

How scoring works

Everything is relative to your own history

This is the part that matters most. "60,000 SOL of volume" means nothing on its own — but "double your usual volume" means a lot. So each signal is scored against the average of your own past snapshots:

Same as your baseline → scores 50
Double the baseline → scores 100
Half the baseline → scores 25
No history yet → scores 50

Your first run will always read 50 across the board. There's no baseline to compare against yet. The index only starts meaning something once you have a few days of snapshots on file.

Combining into one number

The four sub-scores are multiplied by their weights and summed. The weights live in src/config.js and must add up to 1.0 — they're a starting guess, not a truth, and are meant to be tuned once you have real data.

Timeframes

The four signals can be read over 5m, 1h, 6h or 24h, each shown against the equivalent window before it — so a number always arrives with a direction.

A window can never be finer than the collector

Windows are rolled up from stored snapshots, not fetched per request. Reaching back 24 hours on-chain would mean paging through millions of signatures, which the free tier cannot do. So the collection interval sets the floor: at INTERVAL_MINUTES=5 every window is available, at 30 the 5m button is disabled rather than showing a misleading zero.

Windows fill in as the collector runs. A 24h window needs 24 hours of collection behind it. Until then the panel reports its own coverage — “72 of ~288 readings, about 25% covered” — rather than presenting a partial day as a whole one.

Rates are ratios of sums

Graduation rate and rug rate are computed as the total across the window divided by the total, never as the average of each snapshot’s own rate. Averaging rates would let a quiet snapshot with 3 tokens count as heavily as a busy one with 3,000 — in testing that inflated a 1.10% graduation rate to 50.5%.

Reading the index

The final index maps onto one of five conditions. Four are simple thresholds; the fifth overrides everything.

IndexConditionWhat it means
70–100 Sunny ☀️ Graduations up, volume up, rugs below normal. The friendliest conditions to enter.
45–69 Cloudy ⛅ Normal volume, no clear trend either way. Nothing here rewards rushing.
25–44 Overcast 🌧️ Volume fading, fewer tokens making it off the bonding curve.
0–24 Storm ⛈️ Rugs above normal and tokens collapsing together. Hard conditions.
override Extreme 🌪️ Swings so wild the average stops being meaningful. Needs 12+ snapshots of baseline before it can fire at all.

Calibrate these after about two weeks. Run npm run history and look at the distribution. You want a spread — mostly Cloudy is realistic, but Sunny and Storm should turn up sometimes. If one condition dominates completely, adjust the thresholds in src/config.js.

Running it yourself

No install step and no dependencies. You need Node 18 or newer, and a free Helius key only when you want live data.

STEP 01

Check your Node version

node --version   # needs v18 or higher
STEP 02

Run it on mock data

Works immediately, no API key. Run it a few times to build up some history.

npm run mock
STEP 03

See what you've collected

npm run history
STEP 04

Go live

Get a free key at helius.dev, copy .env.example to .env and paste it in. Then drop the mock flag.

npm run once    # a single live pull
npm start       # keep running every 30 min
STEP 05

Serve the dashboard

Starts on port 3000. The page reads /api/latest for the current reading and /api/history for the series behind the hourly strip and the daily rows.

npm run web

Known limits

Things the index can't do, measured rather than guessed. Read this before you trust a number.

The window is sampled, not read whole

pump.fun ran at 50–195 signatures per second when measured, so a full 30-minute window is 90,000–350,000 transactions and Helius parses only 100 per call. Haboob reads a short slice of each interval instead — SAMPLE_SECONDS, default 120 — and scales the rate-like numbers back up.

Keep SAMPLE_SECONDS constant, or old snapshots stop being comparable
Watch your Helius credit burn for the first day

Rug rate is undercounted

Rug detection works by watching each creator's wallet for a dump, which needs fuller coverage than a sample gives. The absolute rug count is consistently low. It still moves when the market moves, so it works as a relative signal — just don't read the raw number as truth.

Graduation is counted now, not sampled

This used to be the weakest number here: graduations are roughly 0.003% of pump.fun traffic, so no affordable sample ever caught one. They are now read from the migration authority account (39az…UJjg), where ~81% of transactions are the pool creation that is a graduation, alongside creations from the mint authority (TSLv…eokM) at ~96% purity.

That drops a full day of counts from ~21,600 API calls to about 50, and makes them exact rather than extrapolated — for every window, with no stored history. Both purities are measured on each run rather than hardcoded, so the figures stay honest if pump.fun changes how those accounts are used.

The collector reads the same source, so the graduation sub-score can actually move. Sampling reported zero graduations on every single run, and a baseline of zero makes the relative score fall back to a neutral 50 — which meant the heaviest-weighted signal in the index was a constant.

Roughly 6% of fetched transactions are usable

From one measured 20-second sample of 3,871 signatures: 1,944 weren't pump.fun, 1,510 were failed transactions, 174 weren't trades. Only 243 survived. Run with DEBUG_COLLECTOR=1 to print this breakdown yourself.
